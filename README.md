# HTML Editor for Email

HTMLメールを、コードを書かずに作るためのエディタです。
お知らせページ用の書き出しもできます。
**サーバーもデータベースも要りません。** 1枚のHTMLとして動きます。

- プレビュー上で直接クリックして書き換えられます
- テンプレート34件・部品10件が入っています
- 作ったものは HTML / テキスト / `.eml`（メールソフト用）として書き出せます
- 保存先はブラウザの中（localStorage）

---

## 手元で動かす

Node.js があれば動きます。**依存パッケージはありません**（`npm install` は不要）。

```bash
node tools/build.js
```

```bash
node tools/serve.js
```

<http://localhost:8080/> が開きます。

`file://` で直接開かないでください。ブラウザによっては localStorage が
使えず、保存が黙って消えます。確認は必ずサーバー越しに行ってください。

---

## Cloudflare Pages へ置く

`dist/` の中身をそのまま配るだけです。

### 手順

1. **新しいリポジトリを作る**（private を推奨）。既存のサイトとは分けてください。
   同じリポジトリに入れると、片方のコミットでもう片方のビルドが走り、
   アカウント共通の月500デプロイを無駄に消費します。

2. **`dist/` を含めて push します。**
   `.gitignore` は `dist/` を除外していません。**これは意図的です。**
   ビルド済みを置いておけば、Pages 側でビルドが要らなくなります。

3. Cloudflare の **Workers & Pages → 新規 → Pages → Git に接続**。

4. ビルドの設定は**空のまま**にします。

   | 項目 | 値 |
   | --- | --- |
   | フレームワーク プリセット | なし |
   | ビルドコマンド | **空** |
   | ビルド出力ディレクトリ | `dist` |

5. デプロイすると `〜.pages.dev` で開きます。

6. 独自ドメインを使うなら、**カスタムドメインでサブドメインを当てます**
   （例 `editor.あなたのドメイン`）。既存サイトのapexはそのままです。

### 更新するとき

```bash
node tools/build.js
```

`dist/` の変更ごと push すれば、Pages が自動で反映します。

### 中身を自分だけに限りたいとき

Pages のプロジェクトに **Cloudflare Access** をかけると、
指定したメールアドレスでログインした人だけが開けるようになります。
静的サイトは URL を知っていれば誰でも開けるので、
人に見せるつもりが無いうちは掛けておくのが安全です。

## 設定

### `config.json`

```json
{
  "imageBase": "https://htmleditor.karuiya.org/img/"
}
```

テンプレートに入っている見本画像の置き場です。

- **このサイトの中で使うだけ**なら `/img/` のような相対指定でも構いません
- **作った原稿をメールとして送る**なら、絶対URLにしてください
  （例 `https://editor.あなたのドメイン/img/`）。
  相対のままだと、受け取った側で画像が出ません

変えたら `node tools/build.js` をやり直してください。

### 見本画像を作り直す

```bash
node tools/make-images.js
```

`assets/img/` に7枚を書き出します。グラデーションと図形だけで
描いているので、外部の素材は使っていません。

## 保存について

保存先は **ブラウザの localStorage**、このサイトのドメインの下です。
サーバーへは何も送っていません。他の人からは見えません。

### 何がどこに入っているか

localStorage の中の5つの鍵に、すべてJSONで入っています。

| 鍵 | 中身 |
| --- | --- |
| `html-editor:docs` | 原稿。**引き出し2つぶんが1つの鍵に入っています** |
| `html-editor:my-templates` | 自分で登録したテンプレート（最大40件） |
| `html-editor:signatures` | 署名 |
| `html-editor:prompts` | AIへの依頼 |
| `html-editor:settings` | 表示サイズなど |

原稿の形はこうなっています。

```
html-editor:docs
  ├ my      … 「作業中」の引き出し
  │   └ <id> … { title, tags, html, updatedAt, versions[] }
  └ shared  … 「保管」の引き出し（作りは my とまったく同じ）
      └ <id> … { … }
```

**引き出しはそれぞれ、原稿を何件でも持てます。** 上限を決めていません。
「作業中」と「保管」は、名前が違うだけで中身の作りは同じです。
コピーと移動は、片方の枝からもう片方へ入れ替えているだけです。

### 容量

| | |
| --- | --- |
| 原稿1件 | 4〜10KB程度（テンプレート1枚で実測 4.4KB） |
| ブラウザの上限 | **実測で約50MB**（Chrome系。ブラウザと空き容量で変わります） |
| 400件貯めたとき | 1.8MB |

数だけなら、まず足りなくなりません。**先に効いてくるのは版履歴のほうです。**

原稿1件につき、上書き保存のたびに**最大30版**まで残ります。同じ原稿を
何度も直すと、その1件が原稿100件ぶんより重くなることがあります。

いっぱいになったときは、**いちばん版を多く抱えている原稿の版を半分捨てて**
もう一度書きます。それでも入らなければ、理由を添えて止めます。
**原稿そのものが黙って消えることはありません。**

### 消えるとき

ブラウザの「閲覧データを消去」で**サイトデータ**を消すと、一緒に消えます。
シークレットウィンドウでは、閉じた時点で消えます。

**大事な原稿は「書き出す」からHTMLとして手元に落としてください。**
これが唯一の確実なバックアップです。

## 多言語

`locales/index.json` に書いた言語ぶんだけ、ビルドが作ります。

```
dist/index.html        既定の言語
dist/en/index.html     それ以外
```

ヘッダーの右に切り替えの選択肢が出ます。保存はドメイン単位なので、
言語を変えても、それまでの原稿はそのまま見えます。

### 訳の当て方

画面側のコードは書き換えていません。`t('key')` のような呼び出しに直すと、
元のアプリとの差が積み上がるためです。代わりに、**文言が現れる場所を特定して、
そこだけ完全一致で差し替え**ます。

素朴な文字列置換にしないのは、短い語が長い語を食うからです。
「保存」を先に置き換えると「保存先」が壊れます。

辞書の鍵は**日本語の原文そのもの**です。鍵を発明しないので、訳し漏れは画面に
日本語として出ます。空欄や鍵の名前が出るより、ずっと気づけます。
ビルドのときにも件数を報告します。

### 言語を足すとき

```bash
node tools/extract-strings.js      # locales/ja.json を作り直す
node tools/merge-locale.js en      # locales/parts/en-*.json をまとめる
node tools/build.js
```

訳は `locales/parts/<lang>-*.json` に分けて書けます。901件を1つのファイルで
扱うと、どこを直したのか見失うためです。まとめる段階で、**元の文言に無い鍵**
（打ち間違い）を報告します。黙って無視されると気づけません。

言語ごとのフォントと表示名は `locales/index.json` に書きます。

### 内部の値と表示は分けてある

階層の名前（背景・段・枠・部品）は、内部では `backdrop` `section` `panel`
`part` という鍵で扱っています。以前は日本語そのものを識別子にしていましたが、
訳すと `[data-wys-lv="背景"]` という CSS の選択子と合わなくなり、
**エラーも出ないまま選択の枠線だけが消えます**。

新しく文言を足すときも、**内部で比較する値は訳の対象にしない**でください。

## 構成

```
src/
  Index.html        画面の骨組み
  Stylesheet.html   見た目
  JavaScript.html   画面の動き（編集・選択・書き出し）
  Templates.js      テンプレート34件と部品10件
  store.js          保存部。localStorage に置く
tools/
  build.js          1枚のHTMLに束ねる
  serve.js          手元で確かめる用のサーバー
  make-images.js    見本画像を作る
assets/img/         見本画像
dist/               ビルド結果。Cloudflare Pages に置くのはここ
```

### 画面と保存部の境目

画面側は `google.script.run` というひとつの窓口しか知りません。
`store.js` がその窓口を作って受けるので、**画面側のコードは1行も
変えずに**保存先だけを差し替えられます。

窓口は30個あります。1つでも欠けると、そこを呼んだ時点で例外になります。
足すときも減らすときも、両側をそろえてください。

```bash
node tools/check-api.js
```

画面が呼ぶ名前と `store.js` が持つ名前を突き合わせます。

### あとから保存先を変えるなら

同じ窓口を Cloudflare Functions などで実装すれば、
端末をまたいだ保存に移せます。差し替えるのは `store.js` だけです。

## 元になったもの

Google Apps Script 上のアプリとして作ったものを、GASへの依存を外して
独立させたものです。画面側はブラウザだけで動いていたので、
ほぼそのまま使っています。

Googleドライブ・Gmail・共有ドライブに依存していた部分は取り除き、
`store.js` と `.eml` の書き出しに置き換えています。
