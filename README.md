# HTML Editor for Email

HTMLメールを、コードを書かずに作るためのエディタです。
お知らせページ用の書き出しもできます。
**サーバーもデータベースも要りません。** 1枚のHTMLとして動きます。

- プレビュー上で直接クリックして書き換えられます
- テンプレート34件・部品10件が入っています
- 作ったものは HTML / テキスト / `.eml`（メールソフト用）として書き出せます
- 保存先はブラウザの中（localStorage）

---

## 手元で動かす

Node.js があれば動きます。**依存パッケージはありません**（`npm install` は不要）。

```bash
node tools/build.js
```

```bash
node tools/serve.js
```

<http://localhost:8080/> が開きます。

`file://` で直接開かないでください。ブラウザによっては localStorage が
使えず、保存が黙って消えます。確認は必ずサーバー越しに行ってください。

## Cloudflare Pages へ置く

`dist/` の中身をそのまま配るだけです。

### 手順

1. **新しいリポジトリを作る**（private を推奨）。既存のサイトとは分けてください。
   同じリポジトリに入れると、片方のコミットでもう片方のビルドが走り、
   アカウント共通の月500デプロイを無駄に消費します。

2. **`dist/` を含めて push します。**
   `.gitignore` は `dist/` を除外していません。**これは意図的です。**
   ビルド済みを置いておけば、Pages 側でビルドが要らなくなります。

3. Cloudflare の **Workers & Pages → 新規 → Pages → Git に接続**。

4. ビルドの設定は**空のまま**にします。

   | 項目 | 値 |
   | --- | --- |
   | フレームワーク プリセット | なし |
   | ビルドコマンド | **空** |
   | ビルド出力ディレクトリ | `dist` |

5. デプロイすると `〜.pages.dev` で開きます。

6. 独自ドメインを使うなら、**カスタムドメインでサブドメインを当てます**
   （例 `editor.あなたのドメイン`）。既存サイトのapexはそのままです。

### 更新するとき

```bash
node tools/build.js
```

`dist/` の変更ごと push すれば、Pages が自動で反映します。

### 中身を自分だけに限りたいとき

Pages のプロジェクトに **Cloudflare Access** をかけると、
指定したメールアドレスでログインした人だけが開けるようになります。
静的サイトは URL を知っていれば誰でも開けるので、
人に見せるつもりが無いうちは掛けておくのが安全です。

## 設定

### `config.json`

```json
{
  "imageBase": "https://htmleditor.karuiya.org/img/"
}
```

テンプレートに入っている見本画像の置き場です。

- **このサイトの中で使うだけ**なら `/img/` のような相対指定でも構いません
- **作った原稿をメールとして送る**なら、絶対URLにしてください
  （例 `https://editor.あなたのドメイン/img/`）。
  相対のままだと、受け取った側で画像が出ません

変えたら `node tools/build.js` をやり直してください。

### 見本画像を作り直す

```bash
node tools/make-images.js
```

`assets/img/` に7枚を書き出します。グラデーションと図形だけで
描いているので、外部の素材は使っていません。

## デザインのジャンル

同じ内容を、目的に合う見た目で送れるようにする仕組みです。テンプレート一覧の
先頭でジャンルを選ぶと、34件すべてがその見た目で並びます。

| | |
| --- | --- |
| ビジネス | 青の差し色。詰めすぎず、事務的すぎず |
| フォーマル | 明朝体と広めの行間。改まった案内に |
| カジュアル | 丸みと温かい色。ゆるやかな案内に |
| ポップ | 大きな見出しと丸いボタン。告知やキャンペーンに |
| ミニマル | 色を使わず、余白で見せる。通知や事務連絡に |

### 色だけでは足りなかった

はじめは配色だけを差し替えていました。結果は「色が変わっただけ」で、別の
デザインには見えませんでした。当然で、**見た目の印象を決めているのは色ではなく、
文字の組み方と余白**だからです。

いま差し替えているのは6つです。

| | |
| --- | --- |
| 文字の大きさ | 見出しと本文の差。ここが印象をいちばん動かす |
| 字面 | 太さ・字間・行間。ゴシックか明朝か |
| 余白 | 詰めるか、ゆったり取るか |
| ボタン | 角の丸み、大きさ |
| 罫線 | 細い線か、太い線か |
| 色 | 地の色みと差し色 |

実際にどれだけ動いているかは、次で見られます。

```bash
node tools/diff-genres.js CTA        # 数字で比べる
node tools/preview-genres.js CTA     # dist/genres.html に並べて描く
```

```
ジャンル    見出し  本文  行間       ボタンの余白  ボタンの角  差し色
ビジネス    20px    15px  1.5/1.8    14px 32px     6px         #1a73e8
フォーマル  21px    14px  1.73/2.07  16px 44px     0px         #1c3557
カジュアル  23px    16px  1.59/1.91  15px 36px     999px       #b45a0a
ポップ      30px    16px  1.42/1.71  18px 42px     999px       #d81b60
ミニマル    18px    14px  1.74/2.09  13px 30px     0px         #1f2328
```

### 組み方もジャンルで変える

見出しの置き方とボタンの形が、ジャンルごとに変わります。**色や字の大きさより、
「見出しがどう置かれているか」のほうが先に目に入る**ためです。

| ジャンル | 見出し | ボタン |
| --- | --- | --- |
| ビジネス | そのまま | 幅なり・角6px |
| フォーマル | 中央に寄せ、下に罫線 | 幅なり・角なし |
| カジュアル | 左に太い線を立てる | 幅なり・丸 |
| ポップ | 差し色で塗り、白抜き | **幅いっぱい**・丸 |
| ミニマル | 上に線を引く | 幅なり・角なし |

**組み替えではなく、指定を足すだけ**で作っています。要素を入れ替えると、
テンプレートごとの事情（画像の直後、表の中、など）に引っかかって壊れます。
足すだけなら、どこにあっても壊れません。実際、変換の前後で `<td>` の数が
変わらないことを44件すべてで確認しています。

### 順序に意味がある

3か所、順序を間違えて壊しました。**どれも「見分ける手がかりを、先に自分で
消してしまう」形**です。

| 直したもの | 何が起きたか |
| --- | --- |
| ボタンの余白・角 | 先に当てたら、あとの「余白をまとめて動かす」に巻き込まれ、`16px 44px` が `21px 57px`、丸ボタンの `999px` が `2248px` になった |
| 見出しの組み方 | 太さを `normal` に変えたあとに探したので見つからず、フォーマルだけ効かなかった（見分け方が `font-weight:bold` のため） |
| ボタンの幅 | `display:block` にしたあとで余白を当てようとして、見つからなかった（見分け方が `display:inline-block` のため） |

いまの順序は、色 → 文字の大きさ → **見出しの組み方** → 太さ → 行間 → 余白 →
角 → 罫線 → 影 → 書体 → **ボタンの余白と角** → **ボタンの幅**、です。

### なぜテンプレートを5倍書かないか

大手のテンプレート数（Stripo は1,660件）は、その大半が季節ものです。
クリスマス61件という数字は、構造が61通りあるという意味ではなく、**同じ構造を
61通りの見た目で用意した**という意味です。

文面を増やして実現すると 34件 → 170件になり、直すたびに170箇所を触ることに
なります。構造と見た目を分けて掛け算にすれば、**維持するのは34件のまま**です。

一覧そのものを5倍にしていないのも同じ理由です。170枚を眺めるのは探すのが
大変になるだけで、選びやすくはなりません。

### ボタンはいちばん最後に当てる

**順序に意味があります。** はじめはボタンを先頭で処理していました。すると
あとの「余白をまとめて動かす」と「角をまとめて動かす」がボタンにも効き、
指定した `16px 44px` が1.3倍されて `21px 57px` になり、丸ボタンの `999px` は
`2248px` になっていました。

ボタンは絶対値で決めたいので、**他の処理がすべて済んだあとに上書き**します。

### 触っていないもの

- **`#ffffff` は差し替えません。** カードの地であると同時に、色を敷いた
  ボタンに乗る文字の色でもあります。動かすと濃い地に濃い文字が乗ります
- **注意・成功・警告の色は残します。** 注意書きの箱は、どのジャンルでも
  注意書きに見えるべきです
- **地を暗くするジャンルは作りません。** 暗い背景のメールは、受信側のソフトに
  よって文字が反転したり背景が落ちたりします
- **組み方（並び順・段組み）は変えません。** そこはテンプレートの役目です
- **自作テンプレートには当てません。** 利用者が書いたHTMLの色や余白を、
  こちらが書き換えてよいものではありません

### 色を変えたら確かめること

**白文字が乗る地の明るさ**です。ボタンの地を明るくしすぎると、白い文字が
読めなくなります。5ジャンル × 44件（テンプレート＋部品）で、白文字を敷いた
すべての地が4.5以上あることを確認しています。

この確認で2件見つけました。もとの緑（`#1e8e3e`、比4.21）と、カジュアルの
差し色として置いた `#c2610c`（比4.19）です。それぞれ `#16803c`（5.02）と
`#b45a0a`（4.76）に直してあります。

## 保存について

保存先は **ブラウザの localStorage**、このサイトのドメインの下です。
サーバーへは何も送っていません。他の人からは見えません。

### 何がどこに入っているか

localStorage の中の5つの鍵に、すべてJSONで入っています。

| 鍵 | 中身 |
| --- | --- |
| `html-editor:docs` | 原稿。**引き出し2つぶんが1つの鍵に入っています** |
| `html-editor:my-templates` | 自分で登録したテンプレート（最大40件） |
| `html-editor:signatures` | 署名 |
| `html-editor:prompts` | AIへの依頼 |
| `html-editor:settings` | 表示サイズなど |

原稿の形はこうなっています。

```
html-editor:docs
  ├ my      … 「作業中」の引き出し
  │   └ <id> … { title, tags, html, updatedAt, versions[] }
  └ shared  … 「保管」の引き出し（作りは my とまったく同じ）
      └ <id> … { … }
```

**引き出しはそれぞれ、原稿を何件でも持てます。** 上限を決めていません。
「作業中」と「保管」は、名前が違うだけで中身の作りは同じです。
コピーと移動は、片方の枝からもう片方へ入れ替えているだけです。

### 容量

| | |
| --- | --- |
| 原稿1件 | 4〜10KB程度（テンプレート1枚で実測 4.4KB） |
| ブラウザの上限 | **実測で約50MB**（Chrome系。ブラウザと空き容量で変わります） |
| 400件貯めたとき | 1.8MB |

数だけなら、まず足りなくなりません。**先に効いてくるのは版履歴のほうです。**

原稿1件につき、上書き保存のたびに**最大30版**まで残ります。同じ原稿を
何度も直すと、その1件が原稿100件ぶんより重くなることがあります。

いっぱいになったときは、**いちばん版を多く抱えている原稿の版を半分捨てて**
もう一度書きます。それでも入らなければ、理由を添えて止めます。
**原稿そのものが黙って消えることはありません。**

### 消えるとき

ブラウザの「閲覧データを消去」で**サイトデータ**を消すと、一緒に消えます。
シークレットウィンドウでは、閉じた時点で消えます。

**大事な原稿は「書き出す」からHTMLとして手元に落としてください。**
これが唯一の確実なバックアップです。

## 多言語

`locales/index.json` に書いた言語ぶんだけ、ビルドが作ります。

```
dist/index.html        既定の言語
dist/en/index.html     それ以外
```

ヘッダーの右に切り替えの選択肢が出ます。保存はドメイン単位なので、
言語を変えても、それまでの原稿はそのまま見えます。

### 訳の当て方

画面側のコードは書き換えていません。`t('key')` のような呼び出しに直すと、
元のアプリとの差が積み上がるためです。代わりに、**文言が現れる場所を特定して、
そこだけ完全一致で差し替え**ます。

素朴な文字列置換にしないのは、短い語が長い語を食うからです。
「保存」を先に置き換えると「保存先」が壊れます。

辞書の鍵は**日本語の原文そのもの**です。鍵を発明しないので、訳し漏れは画面に
日本語として出ます。空欄や鍵の名前が出るより、ずっと気づけます。
ビルドのときにも件数を報告します。

### 言語を足すとき

```bash
node tools/extract-strings.js      # 文言を洗い出す → locales/_source.json
node tools/merge-locale.js en      # locales/parts/en-*.json をまとめる
node tools/build.js
```

**この順番で流してください。** 訳は `locales/parts/<lang>-*.json` に分けて
書けます。900件を1つのファイルで扱うと、どこを直したのか見失うためです。
まとめる段階で、**元の文言に無い鍵**（打ち間違い）を報告します。
黙って無視されると気づけません。

言語ごとのフォントと表示名は `locales/index.json` に書きます。

| ファイル | 役割 |
| --- | --- |
| `locales/_source.json` | 洗い出した原文の一覧。**自動生成。手で触らない** |
| `locales/parts/<lang>-*.json` | 訳を書く場所 |
| `locales/<lang>.json` | まとめた結果。ビルドが読む |

洗い出す先と訳を置く先を分けているのには理由があります。はじめは両方を
`ja.json` にしていて、洗い出すたびに日本語版の言い換え（「マイドライブ」→
「作業中」）が消えていました。**日本語版だけ元のアプリの言い回しに戻る**
という形で表に出ます。

### 既定の言語も辞書を通る

日本語版で訳すのは、独立版で言い方の変わるところだけです
（`locales/parts/ja-standalone.json`、18件）。書いていない分は原文のまま
通ります。

### 記号の入った訳に気をつける

訳は人が書くので、記号が混じります。英語なら "The AI's reply" のような
アポストロフィです。コード中の文字列に素通しで入れると引用符がそこで閉じ、
**その先のコードが全部壊れます**。画面は真っ白になり、手がかりは
「missing ) after argument list」だけです。

ビルドは引用符と `\` を逃がしますが、**逃がすのは訳を当てたものだけ**です。
元のコードには `"'Hiragino Sans','Yu Gothic'"` のように引用符を含む
リテラルが普通にあります。訳と関係の無いものに手を入れれば、そこが壊れます。
一度それで日本語版まで壊しました。

### 開いた人の言語で振り分ける

既定の言語のページの `<head>` で `navigator.language` を見て、合う言語版が
あればそちらへ送ります。Cloudflare Pages は静的配信なので、サーバー側で
`Accept-Language` を見ることはできません（Functions を足せば可能ですが、
そのために「ビルドしない」構成を崩す価値は無いと判断しました）。

決まりは4つです。

- **自分で選んだ言語が最優先。** 切り替えると `html-editor:lang` に覚え、
  以後は判定より優先します。日本語版を見たいドイツの人が、次に開いたとき
  英語へ飛ばされては使えません
- **飛ばすのは既定の言語のページからだけ。** 行き先には入れないので往復しません
- **判断は `<head>` で。** 画面が組み上がる前に決めるので、日本語が一瞬
  見えることはありません
- **どれにも当てはまらないときは `fallback`（既定 `en`）へ。** ただし
  一覧に日本語があれば日本語のままです

`<link rel="alternate" hreflang>` も併記しているので、検索側には両方の
言語版があることが伝わります。

### 署名には住所を入れる場所を用意してある

商用メールでは、送信者の実在する郵送先の住所を載せることが国によって
求められます（米国の CAN-SPAM 法など）。会社の登記情報まで要る国もあります
（英国の Companies Act 2006）。

要件は国ごとに違うので、この道具は**入れる場所を用意するところまで**を
受け持ち、中身は書く人に委ねています。署名の部品は
「会社・部署／氏名／住所／連絡先」の4行で、住所の行を最初から置いてあります。

### 内部の値と表示は分けてある

階層の名前（背景・段・枠・部品）は、内部では `backdrop` `section` `panel`
`part` という鍵で扱っています。以前は日本語そのものを識別子にしていましたが、
訳すと `[data-wys-lv="背景"]` という CSS の選択子と合わなくなり、
**エラーも出ないまま選択の枠線だけが消えます**。

新しく文言を足すときも、**内部で比較する値は訳の対象にしない**でください。

## 構成

```
src/
  Index.html        画面の骨組み
  Stylesheet.html   見た目
  JavaScript.html   画面の動き（編集・選択・書き出し）
  Templates.js      テンプレート34件と部品10件
  store.js          保存部。localStorage に置く
locales/
  index.json        言語の一覧。フォントと表示名
  _source.json      洗い出した原文（自動生成）
  parts/            訳を書く場所
tools/
  build.js          言語ごとに1枚のHTMLへ束ねる
  extract-strings.js 文言を洗い出す
  merge-locale.js   訳をまとめる
  check-api.js      画面と保存部の窓口を突き合わせる
  serve.js          手元で確かめる用のサーバー
  make-images.js    見本画像を作る
assets/img/         見本画像
dist/               ビルド結果。Cloudflare Pages に置くのはここ
```

### 画面と保存部の境目

画面側は `google.script.run` というひとつの窓口しか知りません。
`store.js` がその窓口を作って受けるので、**画面側のコードは1行も
変えずに**保存先だけを差し替えられます。

窓口は30個あります。1つでも欠けると、そこを呼んだ時点で例外になります。
足すときも減らすときも、両側をそろえてください。

```bash
node tools/check-api.js
```

画面が呼ぶ名前と `store.js` が持つ名前を突き合わせます。

### あとから保存先を変えるなら

同じ窓口を Cloudflare Functions などで実装すれば、
端末をまたいだ保存に移せます。差し替えるのは `store.js` だけです。

## 元になったもの

Google Apps Script 上のアプリとして作ったものを、GASへの依存を外して
独立させたものです。画面側はブラウザだけで動いていたので、
ほぼそのまま使っています。

Googleドライブ・Gmail・共有ドライブに依存していた部分は取り除き、
`store.js` と `.eml` の書き出しに置き換えています。
